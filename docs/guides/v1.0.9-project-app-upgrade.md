# v1.0.9 项目应用升级必做

`v1.0.9` 的项目应用使用独立子域名承载静态网站和 Java、Node.js、Python 等动态服务。新客户可以在安装向导中完成配置；旧版本升级会保留现场配置，因此必须手工合并下列内容。

## 1. 配置项目应用根域

在 `application.properties` 中配置项目应用根域和公开访问协议。根域不带协议、端口或路径：

```properties
base.agent.site.app-domain=apps.example.com
base.agent.site.app-scheme=http
```

纯 HTTP 环境填 `http`。已配置项目通配证书时将协议改为 `https`。

## 2. 配置通配 DNS

在 DNS 服务商为项目根域添加通配解析，指向平台服务器公网 IP。例如 DNS 根域为 `yingpeiai.com` 时，阿里云 DNS 添加 `A` 记录，主机记录填 `*.apps`；最终项目地址为 `p-<项目ID>.apps.yingpeiai.com`。

```bash
getent hosts p-1.apps.example.com
```

## 3. 合并 Nginx 项目应用虚拟主机

升级器会保留现场 `application.properties` 和 `nginx/devops.conf`。比较升级后的新模板，只合并新增配置键、`map` 和项目应用虚拟主机：

```bash
diff -u application.properties application.properties.example
diff -u nginx/devops.conf nginx/devops.conf.example
```

Nginx 必须保留两个 `server`：

- 平台主域名使用一个 `server`，提供平台页面、API、SSE 和 WebSocket。
- `p-<项目ID>.<项目根域>` 使用另一个 `server`，完整保留新模板中的项目应用网关配置。
- 两个虚拟主机使用同一个公开 `listen`。HTTP 通常同为 `80`，HTTPS 通常同为 `443`。
- 不要把项应用改成平台主域名下的 `location`，也不要整份覆盖已配置的域名、证书和端口。

项目应用不需要向公网额外暴露 `3000`、`8082` 或 Agent 内部端口。

## 4. 检查并完成真实访问

```bash
sudo nginx -t
sudo systemctl reload nginx
sudo nginx -T | grep -E 'server_name|app-gateway|project-app'

./devops.sh check
./devops.sh start
./devops.sh status
```

`check` 必须显示平台主域名与项目应用共用公开端口，且项目应用网关已进入 Nginx 生效配置。随后从平台项目页面启动并打开一个项目应用，完成最终验收。

## HTTP 与 HTTPS

- HTTP 环境使用同一个公开 `80` 端口即可。
- HTTPS 环境使用同一个公开 `443` 端口，并为 `*.apps.example.com` 配置通配证书。

## 手工添加的外部服务

用户手工添加的外部项目服务仍由浏览器 iframe 直接访问原始 URL，不经过项目应用网关。这类网站只需根据页面提示处理 `X-Frame-Options`、CSP `frame-ancestors` 和跨站 Cookie 限制。

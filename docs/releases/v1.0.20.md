# Agents Platform v1.0.20

## 版本概览

`v1.0.20` 重点加固多项目服务、端口管理、平台重启恢复和异常 Agent 重置，解决项目应用 JSON 被破坏、单个服务拖累整个 Agent，以及端口冲突难定位的问题。

## 主要更新

- 同一 Agent 的多个项目、多个服务和多个端点统一使用稳定端口登记；启动前检测占用，停止后保留，重启继续复用，删除服务后释放。
- 项目应用接口不再被平台代理追加额外响应内容，普通 HTTP、JSON、上传、SSE 和 WebSocket 继续使用项目子域名访问。
- 平台重启后 Agent 会更快重新连接，并立即恢复项目服务通道，减少后端已经启动但项目页面仍打不开的等待时间。
- 单个项目服务构建或启动失败只影响该服务，其他项目和服务继续同步、恢复和访问。
- 最高管理员可对异常 Agent 执行重置，重新初始化运行环境和 SDK；项目目录与聊天上传文件保留，会话、定时任务和产物记录按确认内容清理。
- 全局看板显示每个 Agent 的项目服务端点、稳定端口、冲突、预留、未声明监听和未知监听；离线 Agent 会明确显示异常。
- 项目服务 Skill 与 MCP 增加多服务、多端点的启动、停止、重启、日志和端口检查说明，减少不同项目互相抢占端口。
- JDK、Maven、pnpm 内容没有变化，不重复提供软件离线包，继续复用 `v1.0.15` 软件包和服务器缓存。
- 修复了已知问题。

## 升级说明

1. 升级前备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`。
2. 执行 `docker load -i devops-runtime-images-v1.0.20-linux-amd64.tar` 导入七个本版本运行环境。
3. 执行 `./devops.sh upgrade --check /tmp/devops-v1.0.20-linux-x64.tar.gz`，确认版本、配置差异和包结构。
4. 完成累计升级后运行 `./devops.sh check`，启动服务并等待 Agent 重新连接和运行环境更新。
5. 本版本没有新增 Nginx 参数；现场仍需保留项目服务 WebSocket 分流、连接复用、长连接、上传和非缓冲配置。执行 `nginx -t` 后再重载。
6. 打开一个真实项目服务，连续刷新 JSON 页面并检查上传、SSE 或 WebSocket；在全局看板确认端点和端口状态与 Agent 在线状态一致。
7. Agent 重置只在确定运行环境无法恢复时使用。确认弹窗列出的删除内容，项目文件虽会保留，但会话、定时任务和产物记录不会保留。
8. 需要离线安装 JDK、Maven 或 pnpm 时继续使用 `devops-runtime-software-v1.0.15-linux-amd64.tar.gz`。

同版本与降级仍会被拒绝。程序回滚不会自动回滚数据库，升级前必须保留可恢复备份。

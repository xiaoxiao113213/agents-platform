# Agents Platform v1.0.43

发布日期：2026-08-27

`v1.0.43` 完善 Agent 分享后的项目操作能力。成员可以在管理员授予的范围内完成对话、工具和协作空间工作，同时保留 Agent 全局配置与删除操作的明确边界。

## 本次更新

- “全部项目”分享覆盖 Agent 当前和后续创建的全部项目；“指定项目”分享只开放管理员选择的项目。
- 获授权成员可以使用项目内对话、文件、Skill、MCP、Workflow、应用、项目服务和计划任务等能力。
- 具备创建权限的共享成员新建项目后，项目会自动进入其授权范围，无需管理员再次补配。
- 共享成员可以重命名已授权项目；普通成员只能删除自己创建的项目，Agent 所有者和最高管理员保留更完整的项目治理能力。
- Agent 全局环境、API Key 和分享管理继续仅向 Agent 所有者及最高管理员开放；终端仍需单独授予终端权限。
- Agent 绑定的 Issue 协作空间会同步提供事项、评论、状态和资料操作能力。
- Developer SDK 改进默认网络请求兼容性，业务工作台案例新增统一的启动、状态、健康、日志、重启和停止入口。
- 开发者中心的用量指标和下载资源卡片调整了信息层级与键盘焦点反馈。

## 兼容性

- 本版本不新增域名、DNS、证书、公开端口或生产配置键。
- 现有账号、角色、Agent、项目、会话、分享关系、Issue 协作空间、开发应用和审计记录保持兼容。
- 升级后，历史上由共享成员创建且仍有效的项目会继续保留访问权限。
- 默认 Agent 仍不可删除或转移，Agent 至少保留一个项目的保护规则保持不变。

## 安装与升级

1. 执行 `docker load -i devops-runtime-images-v1.0.43-linux-amd64.tar`，再执行 `./devops.sh images status`，确认所有运行环境均可用。
2. 执行 `./devops.sh update --check` 或 `./devops.sh upgrade --check /tmp/devops-v1.0.43-linux-x64.tar.gz`，只读核对版本、包结构和现场配置差异。
3. 完成备份后按 `./devops.sh stop`、`./devops.sh upgrade /tmp/devops-v1.0.43-linux-x64.tar.gz`、`./devops.sh check`、`./devops.sh start`、`./devops.sh status` 的顺序完成升级。
4. 使用一个“全部项目”分享账号确认当前及新建项目均可访问，再使用“指定项目”分享账号确认只能访问授权项目。
5. 在授权项目内验证一次对话、文件或 Skill/MCP 操作；如已绑定 Issue 协作空间，再验证事项和资料操作。

升级前请备份数据库、安装目录和现场配置。现场 `application.properties` 与 `nginx/devops.conf` 应继续保留；程序回滚不会自动回滚数据库。

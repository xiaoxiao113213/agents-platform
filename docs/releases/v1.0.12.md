# Agents Platform v1.0.12

发布日期：2026-08-13

`v1.0.12` 完善项目资料、会话、服务入口和终端权限，让团队可以在同一个 Agent 项目中更稳定地开发、协作和交付。

## 本次更新

- Issue 项目新增资料工作台，可按目录沉淀 Markdown 文档、文件和外部链接，并通过草稿、审核、发布、历史版本和 Issue 关联形成长期项目背景。
- AI 处理 Issue 时可以先读取项目资料，也可以把经过确认的结论沉淀回资料库，需求管理和知识积累形成闭环。
- 对话附件支持站内预览，常用文本、代码、Markdown、图片、PDF、音视频无需下载即可查看。
- 新建会话会立即出现在左侧；快速重复点击只创建一个会话，刷新后仍保持唯一、可用和选中状态。
- 新会话首次执行后会自动切换到真实会话，执行过程和最终内容无需再次刷新或重复发送。
- Agent 在对话中开发出新的项目服务后，当前项目的服务入口会自动出现，无需刷新页面。
- 角色管理新增 Agent 终端权限；授权后，成员可以在自己有权访问的 Agent 项目中使用终端，未授权时按钮和入口均不可用。
- 项目文件按代码、文档、演示、数据和素材等类型规范放置；已有工程不会被自动迁移或覆盖。
- 新建或重建 Agent 的最低配置统一为 2 核、2048 MB，减少长任务被系统强制中止的情况。
- JDK、Maven 和 pnpm 支持服务器一次准备、全部 Docker Agent 和 Linux 远程 Agent 复用，安装过程不再让每个 Agent 反复访问公网。
- 视频制作 Agent 增加完整镜头制作库，可按成熟镜头配方完成真实产品页面采集、空间运镜、节奏卡点和声音设计，并继续自动生成旁白和检查成片。
- Agent 重建会跟随当前 Agent 类型的最新运行环境，停机 Agent 也不会继续使用历史版本。
- 修复了已知问题。

## 安装与升级

- 新客户可以使用本版本在 Linux x64 环境中连接空的 MySQL 8 数据库完成全新安装。
- `v0.0.1` 及后续正式版本都可以直接累计升级到 `v1.0.12`，无需补装中间版本；升级前可先使用只读检查命令确认环境和配置差异。
- 已安装客户先获取 `devops-runtime-images-v1.0.12-linux-amd64.tar` 并执行 `docker load -i devops-runtime-images-v1.0.12-linux-amd64.tar`，确认导入成功后再执行 `./devops.sh update`。
- 需要为 Agent 安装 JDK、Maven 或 pnpm 时，将 `devops-runtime-software-v1.0.12-linux-amd64.tar.gz` 一次解压到 `/opt/devops/devops/runtime-software-cache`；平台会自动校验并复用。
- 升级不会自动覆盖现场 `application.properties`、Nginx 配置、项目工作区、会话、Skill、MCP、运行数据和日志。
- 本版本新增可选的 Agent 软件离线缓存目录，默认就是安装目录下的 `runtime-software-cache`，通常无需修改配置。使用项目应用独立地址时，继续沿用既有通配 DNS 与 Nginx 项目应用虚拟主机配置。
- 跨较大版本升级前，请在数据库备份副本上核对业务数据，并备份数据库、安装目录和实际配置文件。
- 程序回滚不会自动回滚数据库，恢复旧程序前必须确认数据库兼容或同时恢复升级前备份。

生产环境要求 Linux x64、Java 21+、MySQL 8 与 Docker。详细步骤请参阅官网部署指南和安装包内说明。

# Agents Platform v1.0.24

## 版本概览

`v1.0.24` 重点提升长会话、远程 Agent 同步和 Windows 项目服务的稳定性，并限制单个对话的子 Agent 并发，避免一个窗口占满模型服务。

## 主要更新

- 长会话超过当前模型上下文窗口时会自动压缩并在必要时使用有界上下文继续，完整可见历史、浏览器地址、会话名称和后续操作保持不变。
- 没有生成可见回复的异常回合会自动重试一次；仍失败时给出明确提示，不再显示成功或额外创建一个新对话。
- 新建、运行和切换多个对话时，各自的消息、运行状态与左侧会话项保持隔离，旧会话的延迟状态不能覆盖当前窗口。
- 每个对话默认最多同时运行两个子 Agent，更多任务按批次等待；不同对话使用独立名额，互不阻塞。
- 远程 Agent 重复同步或平台重启时会及时清理旧连接，避免连接与句柄长期累积后无法恢复。
- Windows Agent Runtime 升级不再依赖 PowerShell 可选模块，在受限 PowerShell 5.1 环境中也能完成归档校验和同步。
- Windows 项目服务启动、重启和停止不再因后台服务继承脚本输出而等待两分钟；构建与运行日志句柄会在所有结果路径正确释放。
- 已有单服务的日常升级使用固定最短路径，只检查一次环境、发布一次目标服务并确认一次状态，不再重复扫描源码、改脚本、构建其它服务或启动额外子任务。
- 清单移除构建命令后，平台会同步清理旧配置，避免服务发布成功后又被后台重复构建、停止或更换进程。
- 项目服务继续使用统一生命周期脚本和稳定端口，支持状态、日志、启停、重启和删除的完整闭环。
- JDK、Maven、pnpm 软件内容没有变化，继续复用 `v1.0.15` 软件离线包和服务器缓存。
- 修复了已知问题。

## 升级说明

1. 升级前备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`。
2. 执行 `docker load -i devops-runtime-images-v1.0.24-linux-amd64.tar` 导入本版本运行环境。
3. 执行 `./devops.sh upgrade --check /tmp/devops-v1.0.24-linux-x64.tar.gz`，确认版本、配置差异和包结构。
4. 完成累计升级后运行 `./devops.sh check`，启动服务并等待 Agent 重新连接。
5. 打开一个已有长会话继续发送，再同时建立两个新对话并交替发送，确认地址、标题、消息和运行状态不会串到其它对话。
6. 发起一个包含多个独立子任务的对话，确认同一对话最多同时运行两个子 Agent，其它对话仍能正常使用。
7. 在 Windows 与 Linux Agent 各选择一个真实项目服务，依次验证状态、日志、重启、停止、启动和删除，确认平台端口与实际监听一致。
8. 本版本没有新增平台 Nginx 参数，升级器会保留现场配置；执行 `nginx -t` 后再重载。
9. 需要离线安装 JDK、Maven 或 pnpm 时继续使用 `devops-runtime-software-v1.0.15-linux-amd64.tar.gz`。

同版本与降级仍会被拒绝。程序回滚不会自动回滚数据库，升级前必须保留可恢复备份。

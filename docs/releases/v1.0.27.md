# Agents Platform v1.0.27

## 版本概览

`v1.0.27` 完善项目服务的运行边界，并升级全局 Token 用量看板：平台公开地址只是当前 Agent 工程服务的转发入口，服务仍在原工程中以唯一进程运行；管理员可以按用户、API Key 和实际模型核对精确用量。

## 主要更新

- 项目服务的 Agent 本地入口与平台公开入口统一访问同一个服务进程、同一份数据和同一套生命周期。
- 应用监听端口、公开域名、网关入口、挂载路径和健康路径始终取自当前平台状态，不使用示例、截图或历史环境值。
- 同一服务只保留一个受管进程；创建、更新、重启和停止不会在其它位置部署第二份应用。
- 发布成功后自动记录服务工程目录、生命周期入口、当前端点和公开地址，后续对话可以继续使用正确的服务事实。
- 每次执行服务动作前仍会重新读取当前状态，已记录的端口和地址仅用于理解最近一次发布结果，不会成为固定配置。
- 全局看板分别展示非缓存输入、缓存创建、缓存读取和输出 Token，并按实际 API Key、模型、提供商及模型容量属性提供明细。
- 支持今日、本周、本月、自定义区间、按天或按周聚合，以及用户、API Key、模型、来源和统计精度组合筛选。
- 当前筛选结果可导出 CSV；历史兼容数据与新版本精确数据会明确区分，避免把旧口径误认为可追溯的完整明细。
- 本版本不新增域名、DNS、Nginx、证书或公开端口配置要求，升级器继续保留现场配置。
- JDK、Maven、pnpm 软件内容没有变化，继续复用 `v1.0.15` 软件离线包和服务器缓存。
- 修复了已知问题。

## 升级说明

1. 升级前备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`。
2. 执行 `docker load -i devops-runtime-images-v1.0.27-linux-amd64.tar` 导入本版本运行环境。
3. 执行 `./devops.sh upgrade --check /tmp/devops-v1.0.27-linux-x64.tar.gz`，确认版本、配置差异和包结构。
4. 完成累计升级后运行 `./devops.sh check`，启动服务并等待 Agent 重新连接。
5. 在一个真实项目中更新并重启项目服务，确认应用读取平台当前分配的端口。
6. 分别从 Agent 本地入口和平台返回的公开地址访问同一业务数据，确认两者对应同一实例。
7. 继续一次后续对话，确认 Agent 能识别已经发布的服务，并通过项目服务能力执行状态或重启动作。
8. 使用一个真实 Agent 完成一次对话，再到全局看板按用户、API Key 和模型筛选，核对四类 Token，并导出 CSV。
9. 本版本没有新增平台 Nginx 参数；执行 `nginx -t` 后再重载现场配置。
10. 需要离线安装 JDK、Maven 或 pnpm 时继续使用 `devops-runtime-software-v1.0.15-linux-amd64.tar.gz`。

同版本与降级仍会被拒绝。程序回滚不会自动回滚数据库，升级前必须保留可恢复备份。

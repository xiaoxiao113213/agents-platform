# Agents Platform v1.0.18

## 版本概览

`v1.0.18` 重点提升对话、大文件传输和项目服务长时间运行的稳定性，并让项目能力和管理员诊断更贴近真实运行状态。

## 主要更新

- 对话前台与后台任务使用统一运行状态，后台工作未结束时不再提前收尾或刷新整个页面。
- 文件、产物和远程工作区使用流式分片、完整性校验和有界流控，大文件下载与异常恢复更加稳定。
- 项目服务 HTTP、SSE、WebSocket、上传和下载具备多通道隔离、背压、连接保活和平台重启恢复能力。
- 单个慢请求或慢浏览器只影响自身，不再阻塞同一 Agent 的其他项目服务。
- Skill 与 MCP 统一在当前 Agent 工作区管理，并可直接查看、搜索和维护当前项目已有 Skill。
- 定时对话从上一次执行完成后计算固定间隔，同一会话严格串行，避免重复并发。
- 管理员可按用户进入对应 Agent 和项目，并查看节点、项目服务和隧道的真实状态；离线 Agent 不再显示正常。
- 新建远程 Agent 目录不允许空格，历史带空格目录继续兼容管理和迁移。
- 会话文件上限统一为 500 MiB，超过限制时会在传输前给出明确提示。
- JDK、Maven、pnpm 内容没有变化，不重复提供软件离线包，继续复用 `v1.0.15` 软件包和服务器缓存。
- 修复了已知问题。

## 升级说明

1. 升级前备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`。
2. 执行 `docker load -i devops-runtime-images-v1.0.18-linux-amd64.tar` 导入七个本版本运行环境。
3. 执行 `./devops.sh upgrade --check /tmp/devops-v1.0.18-linux-x64.tar.gz`，确认版本、配置差异和包结构。
4. 停止服务后执行正式累计升级，再运行 `./devops.sh check`、启动服务并检查状态。
5. 升级器会保留现场 Nginx。请从 `nginx/devops.conf.example` 合并 WebSocket 分流、上游连接复用、长连接超时、请求标识、耗时日志和工作区下载非缓冲路由；保留现场域名、证书和端口。
6. 合并后执行 `sudo nginx -t && sudo systemctl reload nginx`，并用一个真实项目持续验证页面、下载、SSE 和 WebSocket。
7. 需要离线安装 JDK、Maven 或 pnpm 时继续使用 `devops-runtime-software-v1.0.15-linux-amd64.tar.gz`。

完整配置键、Nginx 合并内容和验收命令见官网“Linux 安装与升级”页面的“v1.0.18 项目服务”章节。

同版本与降级仍会被拒绝。程序回滚不会自动回滚数据库，升级前必须保留可恢复备份。

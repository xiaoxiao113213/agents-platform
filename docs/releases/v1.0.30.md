# Agents Platform v1.0.30

## 版本概览

`v1.0.30` 新增面向项目工作的第二套平台界面，同时完整保留经典界面的业务能力。部署方可以在安装时选择界面，也可以在不迁移数据、不重启后端的情况下切换；每位用户的第一个 Agent 作为长期默认 Agent，项目需求可直接进入真实项目工作区。

## 主要更新

- 新增项目式界面，以项目入口、最近项目和真实 Agent 工作区为主要操作路径；经典界面的 Agent、Skill、MCP、Issue、系统管理和工作区能力均保留。
- 用户已有 Agent 时，以最早创建的有效 Agent 作为默认 Agent；新用户自动创建默认 Agent。默认 Agent 不可删除、不可转移，删除账号时由平台一并清理。
- 项目首页输入需求后会在默认 Agent 中创建真实项目并进入草稿会话，不再使用“问答、规划、执行”等模式标签。
- Linux 包同时携带 `classic` 与 `project` 两套 Web。首次安装可用 `install --web` 选择，安装后可用 `web use` 安全切换；升级会保留已有选择。
- 数据库设计页面和数据库专用 Agent 已退役；历史 Agent 容器、项目、会话、工作区与产物记录继续保留。
- Runtime 镜像清单调整为 6 个固定版本镜像，数据库专用 Agent 镜像不再进入新版本交付包。
- JDK、Maven、pnpm 软件内容没有变化，继续复用 `v1.0.15` 软件离线包和服务器缓存。
- 修复了已知问题。

## 安装与升级

### 前置条件

- 继续使用 Linux x64、Java 21+、MySQL 8、Docker 和独立 Nginx；本版本不新增配置键、DNS、证书、公开端口或外部服务要求。
- 执行 Web 切换的服务账号需要能够运行 `nginx -t` 并 reload Nginx；非 root 账号需具备对应的 `sudo` 权限。
- 升级前备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`。

### 升级步骤

1. 执行 `docker load -i devops-runtime-images-v1.0.30-linux-amd64.tar` 导入本版本 6 个运行环境镜像，再执行 `./devops.sh images status`。
2. 必要时先运行 `curl -fsSL https://mmmqaz.cn/releases/update-launcher.sh | bash`，并确认 `./devops.sh launcher-version` 不低于 `15`。
3. 执行 `./devops.sh upgrade --check /tmp/devops-v1.0.30-linux-x64.tar.gz`，确认版本、配置差异和包结构。
4. 对比 `nginx/devops.conf` 与 `nginx/devops.conf.example`，只把平台静态根目录合并为 `root <安装目录>/web/current;`；保留现场 `listen`、`server_name`、证书、代理和其它自定义内容。
5. 执行 `sudo nginx -t`，通过后再运行 `./devops.sh stop`、`./devops.sh upgrade /tmp/devops-v1.0.30-linux-x64.tar.gz`、`./devops.sh check`、`./devops.sh start` 和 `./devops.sh status`。
6. 执行 `./devops.sh web status` 查看当前选择。需要项目式界面时运行 `./devops.sh web use project`，需要经典界面时运行 `./devops.sh web use classic`；命令会校验目标资源和 Nginx，失败时自动恢复原界面。
7. 登录后确认经典界面原有菜单和业务可访问；切换到项目式界面，确认最近项目、项目列表、Agent、Skill、MCP、Issue、系统管理与原工作区深链可访问。
8. 在项目首页输入一条需求，确认平台在默认 Agent 中创建真实项目并进入工作区；确认默认 Agent 的删除和转移入口不可用。
9. 确认数据库设计菜单与数据库专用 Agent 不再出现，历史 Agent 项目、会话和产物仍可访问。

### 全新安装

- 默认安装经典界面：`./devops.sh install --web classic`。
- 安装项目式界面：`./devops.sh install --web project`。
- 安装完成后仍可使用 `./devops.sh web use classic|project` 切换，不需要迁移数据库或修改后端配置。

同版本与降级仍会被拒绝。程序回滚不会自动回滚数据库，升级前必须保留可恢复备份；回滚到旧单 Web 版本时，启动器会提供经典界面兼容入口，并保留项目式界面偏好供后续再次升级使用。

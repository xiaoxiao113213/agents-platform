# Agents Platform v1.0.10

发布日期：2026-08-12

`v1.0.10` 重点提升多人共享会话、长任务消息和远程 Agent 的稳定性。任务执行、工具过程、最终回复与刷新后的历史保持一致，Windows 和 Linux 远程 Agent 也拥有统一的安装、升级与终端体验。

## 本次更新

- 对话中的消息、任务进度、工具结果和最终回复保持稳定顺序，减少运行中闪动、重复、消失以及刷新后结果才出现的问题。
- 模型服务返回错误、任务停止或执行中断时展示清晰结果；已完成历史落盘后不再重复显示实时消息。
- API Key 和模型只在当前会话实际执行期间锁定，任务结束、失败或停止后即可继续选择，不影响其他空闲会话。
- Windows 与 Linux 远程 Agent 统一提供安装、启动、停止、重启、升级、状态和日志命令，并在平台中展示当前 Runtime 是否需要升级。
- 远程终端的输入、输出、尺寸调整和断线重连更加稳定，重启远程 Agent 时会确保只保留一个有效进程。
- 重建内置 Agent 时保留默认项目中的已有内容；远程项目添加项目应用、Skill 或 MCP 后会同步到对应项目目录。
- Docker Agent 的运行记录与实际容器短暂失配时，可自动恢复唯一的有效关联；存在重复候选时会停止操作并给出明确处理提示，避免误操作项目工作区。
- 修复了已知问题。

## 安装与升级

- 新客户可以使用本版本在 Linux x64 环境中连接空的 MySQL 8 数据库完成全新安装。
- `v0.0.1` 及后续正式版本都可以直接累计升级到 `v1.0.10`，无需补装中间版本；升级前可先使用只读检查命令确认环境和配置差异。
- 已安装客户可以先独立更新启动器，再使用 `./devops.sh update` 在线升级；运行环境也可以通过独立命令提前下载，并持续显示下载进度。
- 升级不会自动覆盖现场 `application.properties`、Nginx 配置、项目工作区、会话、Skill、MCP、运行数据和日志。
- 本版本没有新增生产配置项。使用项目应用独立地址时，仍需完成 `v1.0.9` 引入的项目根域通配 DNS 与 Nginx 项目应用虚拟主机配置。
- 跨较大版本升级前，请在数据库备份副本上核对业务数据，并备份数据库、安装目录和实际配置文件。
- 程序回滚不会自动回滚数据库，恢复旧程序前必须确认数据库兼容或同时恢复升级前备份。

生产环境要求 Linux x64、Java 21+、MySQL 8 与 Docker。详细步骤请参阅官网部署指南和安装包内说明。

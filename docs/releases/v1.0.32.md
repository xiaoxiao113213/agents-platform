# Agents Platform v1.0.32

## 版本概览

`v1.0.32` 重点完善多项目日常协作和项目应用可靠性。最近项目会跟随真实对话活动更新；Agent 共享可以控制具体项目和创建项目权限；大型工作区改为逐层加载。项目协作资料、角色主题、Agent 管理入口和两套 Web 的视觉细节也同步收口。

本版本还修复了两个会直接打断工作的链路：模型报错后切换模型可以立即继续，不再要求刷新页面；项目应用的 JSON POST 会按原请求类型正常穿过平台网关，不再需要改成文本请求规避等待。

## 主要更新

- 最近项目增加到 10 个，并按项目中最近一次真实会话活动排序；在非默认项目对话后，首页和侧栏会正确更新。
- Agent 卡片在单项和多项场景保持稳定宽度，支持重命名和直接进入完整管理页。
- 项目卡片明确展示所属 Agent 和真实运行状态，减少把 Agent 状态误解为项目进度的情况。
- 项目协作汇总统一展示 AI 待审事项与资料；待审资料有明确标签，资料文件支持由 Agent 创建、替换和重命名。
- Agent 共享支持“全部项目”和“指定项目”两种范围，并可独立控制共享成员能否创建项目。
- 工作区文件树按目录逐层、分页加载，大型项目可以继续浏览超过单页数量的文件和目录。
- 角色可以绑定多个界面主题，用户继续按已拥有的角色与主题组合切换并保留选择。
- 对话模型报错后切换模型会立即保存并用于下一条消息，保存完成前会避免误发到旧模型。
- 项目应用网关完整保留 JSON POST 的请求正文和类型，同时继续支持上传、流式响应与 WebSocket。
- Classic 与 Project 两套 Web 同步修正 Logo 比例、主题背景、工具栏位置、角色回显和单 Agent 布局。
- 本版本不新增域名、DNS、Nginx、证书、公开端口或外部服务要求，现场配置继续保留。
- 修复了已知问题。

## 安装与升级

### 前置条件

- 继续使用 Linux x64、Java 21+、MySQL 8、Docker 和独立 Nginx。
- 项目应用继续沿用既有项目根域、通配 DNS、证书和 Nginx 项目应用虚拟主机；已经可访问项目子域名的环境无需新增配置。
- 升级前备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`。
- 确认磁盘空间足够保存并导入六个运行环境；运行环境包和主程序包必须同为 `v1.0.32`。

### 升级步骤

1. 执行 `docker load -i devops-runtime-images-v1.0.32-linux-amd64.tar`，再执行 `./devops.sh images status`，确认六个运行环境均可用。
2. 必要时先运行 `curl -fsSL https://mmmqaz.cn/releases/update-launcher.sh | bash`，并确认 `./devops.sh launcher-version` 不低于 `15`。
3. 执行 `./devops.sh upgrade --check /tmp/devops-v1.0.32-linux-x64.tar.gz`，确认版本、包结构和现场配置差异。
4. 执行 `./devops.sh stop`、`./devops.sh upgrade /tmp/devops-v1.0.32-linux-x64.tar.gz`、`./devops.sh check`、`./devops.sh start` 和 `./devops.sh status`。
5. 不要覆盖现场 `application.properties` 或 `nginx/devops.conf`。若项目应用虚拟主机曾做过现场修改，只合并新模板中确实需要的代理参数，并保留原域名、证书和监听端口。

### 产品内验收

1. 登录后打开最近项目，在一个非默认项目中新建或继续会话，返回首页确认该项目顺序更新且显示所属 Agent。
2. 打开一个共享 Agent，确认成员只能看到授权项目；分别核对允许和不允许创建项目的成员行为。
3. 展开包含大量文件的工作区目录，继续加载后续页并使用搜索确认文件可见。
4. 在一个会话中切换模型后直接发送消息，确认输入区显示的模型与实际响应一致；刷新页面后选择保持。
5. 打开包含 JSON POST 的项目应用，提交一次真实表单或接口请求，确认正常返回；再抽查上传、流式输出或 WebSocket 功能。
6. 打开角色、用户和主题页面，确认角色主题多选与用户角色名称正确回显。

### 常见问题

- 项目子域名无法访问：检查通配 DNS 是否指向平台 Nginx，并确认现场证书覆盖 `p-<项目ID>.<项目根域>`。
- 页面可打开但接口失败：确认项目应用虚拟主机仍把原始 Host、URI、请求类型和 WebSocket Upgrade 头转发到平台后端，不要把应用接口单独改写为静态路径。
- 升级预检提示配置差异：保留现场文件，以包内 `.example` 为参考逐项合并；不要直接覆盖域名、证书、数据库连接和本地存储目录。
- 模型切换保存失败：先确认当前 Agent 在线且 API Key 仍包含目标模型，再重新选择；不要通过刷新规避持续存在的配置错误。

### 全新安装

- 默认安装经典界面：`./devops.sh install --web classic`。
- 安装项目式界面：`./devops.sh install --web project`。
- 安装完成后可使用 `./devops.sh web use classic|project` 切换，两套界面共用账号、权限、Agent、项目和会话数据。

同版本与降级仍会被拒绝。程序回滚不会自动回滚数据库，升级前必须保留可恢复备份；升级和回滚都不会覆盖现场配置、项目工作区、文件与运行数据。

# Agents Platform v1.0.39

发布日期：2026-08-26

`v1.0.39` 重点提升 Agent 文件交付的可靠性和速度。用户要求文件时，Agent 会交付真实可下载的文件，不再用平台页面或预览地址替代；大文件也能更早进入下载流程。

## 主要变化

- Agent 在用户要求文件时必须提交真实文件产物，平台页面、应用和预览地址不再被当作文件交付。
- 文件已生成但尚未进入产物列表时，Agent 会继续完成交付，减少只给说明却没有附件的情况。
- 大文件的传输、校验和固化流程优化，同一账号的其他操作不再被长时间排队阻塞。
- 产物处理中会持续刷新状态，固化完成前也可在权限范围内下载工作区原文件。
- 中文和特殊字符文件名的下载兼容性进一步完善。
- 最近项目筛选、Issue 树形字段和 Skill 状态展示同步优化，并修复了已知问题。
- 对话定时执行页面全面优化，任务摘要、计划信息、启停状态和操作入口更清晰；编辑任务改为分区抽屉，加载异常可直接重试。
- 对话工作区的产物、应用、Skill、文件和协作空间入口保持固定顺序；其余工具会根据空间自动收进更多菜单，窄窗口下不再截断。
- 对话仍在运行时也可以创建并进入新项目，原项目任务继续执行，返回原项目即可查看进度。
- 升级前遗留或服务重启时未完成的文件产物会自动恢复处理；原文件仍存在时可在权限范围内先行下载。
- 修复部分兼容模型只返回“正在处理”等过程说明就提前结束的问题；平台会继续推进任务，连续无法产出结果时给出明确错误而不是显示已完成。

## 安装与升级

- 生产环境继续要求 Linux x64、Java 21+、MySQL 8 和 Docker Engine。
- 本版本不新增域名、DNS、证书、Nginx 站点、公开端口、外部服务或生产配置键，现场 `application.properties` 与 `nginx/devops.conf` 必须继续保留。
- 全新安装可在新目录解压主程序包并运行 `./devops.sh install`，使用空的 `devops` 数据库完成初始化。
- 既有环境支持从 `v1.0.38`、`v0.0.1` 及其后的正式版本直接累计升级，无需补装中间版本。
- 升级前先备份数据库、安装目录与现场配置，并准备与主程序同版本的运行环境包。

## 升级步骤

1. 执行 `docker load -i devops-runtime-images-v1.0.39-linux-amd64.tar`，再执行 `./devops.sh images status`，确认所有运行环境均可用。
2. 执行 `./devops.sh update --check` 或 `./devops.sh upgrade --check /tmp/devops-v1.0.39-linux-x64.tar.gz`，只读核对版本、包结构和现场配置差异。
3. 完成备份后按 `./devops.sh stop`、`./devops.sh upgrade /tmp/devops-v1.0.39-linux-x64.tar.gz`、`./devops.sh check`、`./devops.sh start`、`./devops.sh status` 的顺序完成升级。
4. 登录平台发起一次明确要求文件的 Agent 对话，确认最终回复附带真实文件，并检查产物处理、下载文件名和大文件下载体验。

同版本和降级仍会被拒绝。程序目录回滚不会自动还原业务数据库，生产升级前必须保留可恢复的数据库备份。

# Agents Platform v1.0.35

## 版本概览

`v1.0.35` 重点保护长时间工作中的输入与草稿。平台仍会识别新版本，但不会再在后台定时强制刷新；发现可用更新时由用户保存当前内容后主动刷新。

本版本同时将 PC 平台统一为 Project UI，Agent、项目、会话、工作区、协作空间、Skill、MCP 和系统管理能力保持完整，安装与累计升级流程继续兼容既有环境。

## 主要更新

- 当前页面已经是服务端对应版本时，版本检查保持静默，不刷新页面。
- 发现服务端新版本时显示一次更新提示，用户可以暂不刷新或在保存内容后立即刷新。
- 服务端暂时较旧、滚动升级尚未完成或版本响应异常时不会打断当前工作。
- PC 平台统一使用 Project UI，不再维护两套独立界面；现有账号、角色、主题、Agent、项目和会话数据无需迁移。
- 本地与生产构建只生成一份 Project UI，降低两套页面行为不一致的风险。
- 旧版本启动器仍可校验并累计升级到本版本，不要求客户先切换界面或迁移业务数据。
- 本版本没有新增域名、DNS、证书、公开端口或生产配置键，并修复了已知问题。

## 安装与升级

### 前置条件

- 继续使用 Linux x64、Java 21+、MySQL 8、Docker 和独立 Nginx。
- 升级前备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`。
- 确认磁盘空间足够保存并导入 6 个运行环境；运行环境包和主程序包必须同为 `v1.0.35`。
- 保留现场域名、证书、端口、数据库连接和项目应用代理配置。

### 升级步骤

1. 执行 `docker load -i devops-runtime-images-v1.0.35-linux-amd64.tar`，再执行 `./devops.sh images status`，确认 6 个运行环境均可用。
2. 必要时先运行 `curl -fsSL https://mmmqaz.cn/releases/update-launcher.sh | bash`，并确认 `./devops.sh launcher-version` 不低于 `15`。
3. 执行 `./devops.sh upgrade --check /tmp/devops-v1.0.35-linux-x64.tar.gz`，确认版本、包结构和现场配置差异。
4. 执行 `./devops.sh stop`、`./devops.sh upgrade /tmp/devops-v1.0.35-linux-x64.tar.gz`、`./devops.sh check`、`./devops.sh start` 和 `./devops.sh status`。
5. 不要覆盖现场 `application.properties` 或 `nginx/devops.conf`。

### 产品内验收

1. 登录平台并进入一个 Agent 项目，确认项目、历史会话、工作区文件和协作空间数据保持完整。
2. 在输入框写入未发送内容并保持页面打开，确认平台不会周期性自动刷新或清空输入。
3. 打开 Agent、Skill、MCP、协作空间和系统管理页面，确认原有功能均可从 Project UI 使用。
4. 打开版本历史页面，确认 `v1.0.35` 与历史版本说明均可独立查看。

### 常见问题

- 页面提示发现新版本：先保存当前输入或表单，再点击“立即刷新”；也可以选择暂不刷新继续工作。
- 页面仍显示旧界面：确认 Nginx 静态根目录指向当前安装目录的 `web/current`，不要覆盖现场其他 Nginx 配置。
- 升级预检提示配置差异：保留现场文件，以包内 `.example` 为参考逐项合并。

### 全新安装

全新安装执行 `./devops.sh install`，安装完成后直接进入 Project UI。历史 `--web classic|project` 参数为旧启动器兼容入口，两者在本版本中使用相同的 Project UI。

同版本与降级仍会被拒绝。程序回滚不会自动回滚数据库，升级前必须保留可恢复备份；升级和回滚都不会覆盖现场配置、项目工作区、文件与运行数据。

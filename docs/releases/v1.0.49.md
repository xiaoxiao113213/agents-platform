# Agents Platform v1.0.49

发布日期：2026-09-01

`v1.0.49` 完善了 SDK 独立交付、案例初始化、模型路由和对话界面标准，并增强了远程 Agent 项目服务的恢复能力。客户升级后可以直接在原项目中发起一次 Agent 对话，让 Agent 按平台提供的恢复流程检查并恢复服务。

## 本次更新

- 开发者中心统一提供 TypeScript、React、Java SDK、OpenAPI、对话 UI 标准和三个完整案例，支持下载、说明预览、文件树浏览与源码搜索。
- Agent Console、智能客服和 Agent Observatory 三个案例都可作为独立工程交付；基于案例扩展前先复制到项目业务目录，平台后续更新案例源码时不会覆盖客户代码。
- Agent Console 与智能客服案例加入本地用户、首次初始化和持久配置流程，独立部署后可先配置平台地址、SDK API Key、Agent 和运行模型，再进入业务系统。
- 智能客服案例按客户隔离 Agent 项目，同一客户的工单复用其项目并分别保留会话；管理员可按 Agent 选择执行引擎、对应 API Key 和模型。
- SDK 对话界面统一发送即显、流式正文、运行过程、正式历史和终态处理，修复首条消息延迟出现、同轮回复重复、错误后持续等待和历史路由被当前配置覆盖等问题。
- 开发者应用复制 SDK API Key 时会获取完整值，不再把脱敏前缀误当成可用 Key。
- Windows 远程 Agent 的项目服务状态文件异常时，平台会在 Agent 重新连接和打开对话前同步最新恢复能力，避免旧项目继续使用过时指令。
- 项目服务恢复会检查进程身份、端口、监听、健康状态、日志和公开地址；遇到重复端口、未知进程或进程身份不一致时会停止自动操作并给出明确原因。
- 修复了已知问题。

## 项目服务恢复

升级并等待目标远程 Agent 重新在线后，在故障项目的现有会话或新会话中发送：

```text
检查并恢复当前项目服务
```

Agent 会读取项目当前服务定义，先执行一次完整检查，再执行一次权威同步，并核对服务状态、日志、PID、监听端口、健康结果和公开地址。若现场存在无法确认归属的进程、重复端口或进程身份不一致，Agent 不会强制结束进程，而会把阻断原因和下一步操作返回到对话中。

## 安装与升级

1. 执行 `docker load -i devops-runtime-images-v1.0.49-linux-amd64.tar`，再执行 `./devops.sh images status`，确认六个运行环境可用。
2. 执行 `./devops.sh update --check` 或 `./devops.sh upgrade --check /tmp/devops-v1.0.49-linux-x64.tar.gz`，只读核对版本、包结构和配置差异。
3. 备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`，按 `stop -> upgrade -> check -> start -> status` 完成升级。
4. 等待目标 Agent 重新在线，在故障项目中发送“检查并恢复当前项目服务”，核对对话返回的状态、健康结果和公开地址。
5. 打开开发者中心的 SDK 资源页，下载一个完整案例并复制到独立业务目录，按案例初始化向导完成一次平台连接与对话。

本版本没有新增域名、DNS、证书、Nginx 虚拟主机、公开端口或外部服务要求。现场配置和运行数据继续保留；程序回滚不会自动回滚数据库。

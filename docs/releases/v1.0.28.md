# Agents Platform v1.0.28

## 版本概览

`v1.0.28` 重点完善 Agent 持续工作体验和企业级运维可观测性：运行中的追加输入会在输入区排队并依次执行，长任务会持续推进到清晰终态；管理员可以查看主机与用户 Agent 的具体资源数值、七天趋势和 Top 10，同时安全维护 Agent 环境变量。

## 主要更新

- 运行中的新输入显示在输入框上方并按顺序执行，不会打断当前任务，也不会提前混入正式消息历史。
- 工具调用、后台任务和阶段性进度不再被误判为最终答复；任务会继续运行，直到形成最终结果、明确失败或确实需要用户决策。
- 加载更早消息时保持当前阅读位置；快速切换、刷新会话时会忽略过期响应，减少消息来回跳动、重复或错位。
- 最后一条运行中消息显示明确的处理中状态，并在真实终态到达后可靠结束。
- 全局运维看板增加 CPU、内存、磁盘和网络的具体数值、七天趋势及 Top 10，可按用户定位 Agent 资源占用。
- Agent 磁盘指标只统计自身工作区真实占用，兼容 Docker 和 Ubuntu 主机，不再用整台物理机磁盘容量代替。
- 资源采集采用低频、错峰和有界执行，避免监控工作挤占 Agent 对话、项目服务和平台请求。
- Agent 工作台新增环境变量入口；普通变量可维护，密钥变量只显示是否已配置，不回显明文。
- 文件型对话产物会固化到平台，后续可继续下载；源文件移动或 Agent 暂时离线时历史交付更稳定。
- API Key 支持按模型维护计价属性，全局用量看板据此提供可核对的成本估算。
- 本版本不新增域名、DNS、Nginx、证书或公开端口配置要求，升级器继续保留现场配置。
- JDK、Maven、pnpm 软件内容没有变化，继续复用 `v1.0.15` 软件离线包和服务器缓存。
- 修复了已知问题。

## 升级说明

1. 升级前备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`。
2. 执行 `docker load -i devops-runtime-images-v1.0.28-linux-amd64.tar` 导入本版本运行环境。
3. 执行 `./devops.sh upgrade --check /tmp/devops-v1.0.28-linux-x64.tar.gz`，确认版本、配置差异和包结构。
4. 完成累计升级后运行 `./devops.sh check`，启动服务并等待 Agent 重新连接。
5. 在一个真实会话运行任务，并在任务进行中连续追加两条输入，确认两条输入在输入区依次等待、随后按顺序执行。
6. 加载更早消息并继续滚动，确认当前阅读位置稳定；任务运行中确认最后一条消息显示处理中状态。
7. 打开全局看板，核对主机 CPU、内存、磁盘和网络具体数值、七天趋势及 Top 10，再检查一个用户 Agent 的工作区磁盘占用。
8. 在 Agent 工作台新增一个普通变量和一个密钥变量，重新打开后确认密钥值不回显；运行中的项目服务按页面提示重启后再验收变量。
9. 生成一个文件型对话产物并从平台下载，确认历史交付可用。
10. 本版本没有新增平台 Nginx 参数；执行 `nginx -t` 后再重载现场配置。
11. 需要离线安装 JDK、Maven 或 pnpm 时继续使用 `devops-runtime-software-v1.0.15-linux-amd64.tar.gz`。

同版本与降级仍会被拒绝。程序回滚不会自动回滚数据库，升级前必须保留可恢复备份。

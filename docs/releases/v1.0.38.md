# Agents Platform v1.0.38

发布日期：2026-08-25

`v1.0.38` 重点完善 Skill 分类、最近项目和协作空间。平台管理员可以按领域控制能力开放范围，成员可以更快找到当前项目真正可用的 Skill，并从最近项目和任务状态继续工作。

## 主要变化

- 新增 Skill 分类管理，支持创建、查询、编辑、删除、智能归类和人工校准；仍有 Skill 使用的分类会阻止删除，无法判断的内容统一归入“其他”。
- 主题管理增加领域与 Skill 分类的开放关系，支持逐项控制或一键向全部领域开放通用分类。
- 项目添加 Skill 时按当前成员拥有的领域过滤可选范围，并支持按分类快速筛选。
- Skill 与 MCP 能力目录改为卡片浏览，保留搜索、筛选、详情和配置入口。
- 最近项目按实际活动时间展示全部可访问项目，每次加载 10 个；执行中、完成待查看和普通项目状态更容易识别。
- 我的 Agent 支持直接重命名，个人主 Agent 继续保持明确标签。
- 协作空间移至开始导航的项目下方，状态、授权来源和创建人支持组合多选筛选。
- 平台配置和自动化入口统一进入系统管理，并修复了已知问题。

## 安装与升级

- 生产环境继续要求 Linux x64、Java 21+、MySQL 8 和 Docker Engine；升级前确认 Java、数据库、Docker 与磁盘空间满足现有部署手册要求。
- 本版本不新增域名、DNS、证书、Nginx 站点、公开端口、外部服务或生产配置键，现场 `application.properties` 与 `nginx/devops.conf` 必须继续保留。
- 全新安装可在新目录解压主程序包并运行 `./devops.sh install`，使用空的 `devops` 数据库完成初始化。
- 既有环境支持从 `v1.0.37`、`v0.0.1` 及其后的正式版本直接累计升级，无需补装中间版本。
- 升级前先备份数据库、安装目录与现场配置，并准备与主程序同版本的运行环境包。

## 升级步骤

1. 执行 `docker load -i devops-runtime-images-v1.0.38-linux-amd64.tar`，再执行 `./devops.sh images status`，确认所有运行环境均可用。
2. 执行 `./devops.sh update --check` 或 `./devops.sh upgrade --check /tmp/devops-v1.0.38-linux-x64.tar.gz`，只读核对版本、包结构和现场配置差异。
3. 完成备份后按 `./devops.sh stop`、`./devops.sh upgrade /tmp/devops-v1.0.38-linux-x64.tar.gz`、`./devops.sh check`、`./devops.sh start`、`./devops.sh status` 的顺序完成升级。
4. 登录平台，检查 Skill 分类、主题开放范围、最近项目、Agent 重命名和协作空间筛选；再执行一次 Docker Agent 与远程 Agent 对话确认运行正常。

同版本和降级仍会被拒绝。程序目录回滚不会自动还原业务数据库，生产升级前必须保留可恢复的数据库备份。

# Agents Platform v1.0.41

发布日期：2026-08-26

`v1.0.41` 正式开放平台 Agent 能力。团队可以把已有 Agent 安全地接入自己的业务系统，并获得 SDK、React 组件、接口契约和完整案例；运维人员也可以更快定位服务机器上的内存占用来源。

## 主要变化

- 新增开发者中心，可创建独立开发应用，授权所需 Agent 和模型连接，并维护调用凭据、来源校验、限流与审计。
- 应用获得 Agent 后可使用该 Agent 的完整项目能力，包括对话、文件、终端、Skill、MCP、项目服务和运行管理；平台级治理能力不会随 Agent 授权开放。
- 支持服务端长期 API Key 与浏览器短期令牌两种接入方式，Origin 校验可按应用开启或关闭。
- 随平台离线交付 TypeScript SDK、React 接入包、OpenAPI 契约、事件 Schema 和 Node BFF + React 业务工作台案例。
- 运维看板新增服务机器内存进程 Top 10 / Top 20，在 Linux 生产环境中可查看进程、启动命令，并尽可能关联容器、Agent 与所属用户。
- 改善开放接口的鉴权状态、终端连接和模型回退行为，并修复了已知问题。
- 本版本不新增域名、DNS、证书、Nginx 站点、公开端口、外部服务或生产配置键。

## 安装与升级

- 生产环境继续要求 Linux x64、Java 21+、MySQL 8 和 Docker Engine。
- 全新安装可在新目录解压主程序包并运行 `./devops.sh install`，使用空的 `devops` 数据库完成初始化。
- 既有环境支持从 `v1.0.40`、`v0.0.1` 及其后的正式版本直接累计升级，无需补装中间版本。
- 升级前先备份数据库、安装目录与现场配置，并准备与主程序同版本的运行环境包。

## 升级步骤

1. 执行 `docker load -i devops-runtime-images-v1.0.41-linux-amd64.tar`，再执行 `./devops.sh images status`，确认所有运行环境均可用。
2. 执行 `./devops.sh update --check` 或 `./devops.sh upgrade --check /tmp/devops-v1.0.41-linux-x64.tar.gz`，只读核对版本、包结构和现场配置差异。
3. 完成备份后按 `./devops.sh stop`、`./devops.sh upgrade /tmp/devops-v1.0.41-linux-x64.tar.gz`、`./devops.sh check`、`./devops.sh start`、`./devops.sh status` 的顺序完成升级。
4. 登录平台创建一个开发应用，授权测试 Agent 并使用 SDK 案例发起对话；管理员再检查调用审计和运维看板的进程内存排行。

同版本和降级仍会被拒绝。程序目录回滚不会自动还原业务数据库，生产升级前必须保留可恢复的数据库备份。

# Agents Platform v1.0.22

## 版本概览

`v1.0.22` 让项目服务在启动前主动识别资源风险，已有项目自动同步最新服务能力，同时完善 Maven 国内镜像和平台内嵌验收，减少“直接打开正常、平台内不可用”以及资源不足后反复重试的问题。

## 主要更新

- 项目服务在构建、启动和重启前后检查 CPU、内存、已有服务负载、构建峰值和运行稳态；资源不足时主动给出最低配置、推荐配置、资源差额和下一步。
- 启动失败会识别内存不足、进程被系统终止等真实证据，避免无意义重复启动，并区分端口、命令、依赖和应用配置问题。
- 已启用项目服务能力的旧项目会自动同步最新 Skill，无需重新创建项目或手工重装。
- Maven 离线安装默认配置阿里云公共镜像，已有 Maven 配置不完整时可直接修复，无需再次传输软件包。
- 项目服务增加平台内嵌验收，覆盖响应头、内容安全策略、HTTPS、Cookie、登录跳转和关键接口；浏览器直接打开正常不再等同于平台内可用。
- 平台只处理展示兼容，不会关闭项目自身的账号密码、Token、权限或接口鉴权。
- JDK、Maven、pnpm 软件内容没有变化，继续复用 `v1.0.15` 软件离线包和服务器缓存。
- 修复了已知问题。

## 升级说明

1. 升级前备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`。
2. 执行 `docker load -i devops-runtime-images-v1.0.22-linux-amd64.tar` 导入本版本运行环境。
3. 执行 `./devops.sh upgrade --check /tmp/devops-v1.0.22-linux-x64.tar.gz`，确认版本、配置差异和包结构。
4. 完成累计升级后运行 `./devops.sh check`，启动服务并等待 Agent 重新连接。
5. 打开已有项目，确认项目服务能力已同步；执行一次真实构建或启动，检查资源提示、端口、健康状态和服务日志。
6. 在平台项目服务页面中实际打开登录页和关键页面，验证登录、刷新、接口、上传、SSE 或 WebSocket；只在新窗口直接访问成功不算完成。
7. 页面拒绝嵌入时，检查项目应用及其专属代理是否返回拒绝 iframe 的响应头，并确认平台与项目域名都使用 HTTPS。不要关闭项目自身的业务鉴权。
8. 本版本没有新增平台 Nginx 参数，升级器会保留现场配置；执行 `nginx -t` 后再重载。
9. 需要离线安装 JDK、Maven 或 pnpm 时继续使用 `devops-runtime-software-v1.0.15-linux-amd64.tar.gz`。

同版本与降级仍会被拒绝。程序回滚不会自动回滚数据库，升级前必须保留可恢复备份。

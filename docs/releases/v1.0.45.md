# Agents Platform v1.0.45

发布日期：2026-08-28

`v1.0.45` 为 Linux 主服务增加明确、可校验的 JVM 内存和诊断配置。运维人员可以按服务器容量设置初始堆、最大堆、GC 日志和 OOM 堆转储，并直接通过启动器查看实际生效值。

## 本次更新

- 可分别设置主服务 JVM 初始堆与最大堆，减少依赖 Java 自动估算带来的环境差异。
- 启动、重启和前台运行统一使用同一组 JVM 参数，避免不同运行方式下配置不一致。
- 启动前校验数字范围、布尔值和 `Xms <= Xmx` 关系，配置错误会给出明确提示并拒绝启动。
- `./devops.sh status` 与 `./devops.sh check` 会显示解析后的内存和诊断配置，便于升级验收。
- 默认启用固定容量轮转的 GC/安全点日志；发生 OOM 时可在安装目录的 `logs/` 中保留堆转储。
- 六个内置 Agent 运行环境统一更新为 `v1.0.45`。
- 延续对话正文历史持久保存能力；从更早版本累计升级后会继续自动分批补齐尚未恢复的历史。

## 新增配置

升级会保留现场 `application.properties`，不会自动覆盖。请对比新版 `application.properties.example`，将以下四个键和对应中文注释合并到现场文件：

```properties
devops.launcher.jvm-xms-mb=1024
devops.launcher.jvm-xmx-mb=4096
devops.launcher.jvm-gc-log-enabled=true
devops.launcher.jvm-heap-dump-enabled=true
```

- 内存单位均为 MB。某个内存值设置为 `0` 时，仅该项交由 Java 21 自动决定。
- 默认值为 `Xms=1024 MB`、`Xmx=4096 MB`。8 GB 服务器可从 `512/2048` 开始，16 GB 可使用默认值，32 GB 可从 `2048/8192` 开始，再按真实并发和监控调整。
- `Xmx` 只约束 Java 堆，进程还会使用元空间、直接内存、线程栈和本地库内存；还需为 MySQL、Nginx、Docker Engine 和 Agent 容器预留容量。
- GC 日志写入 `logs/gc.log`，最多保留 5 个、每个 20 MB。
- OOM 堆转储写入 `logs/`，大小可能接近最大堆并包含敏感业务数据。请预留磁盘、限制目录访问，并在分析完成后安全清理；不具备这些条件时可将开关设为 `false`。

## 安装与升级

1. 执行 `docker load -i devops-runtime-images-v1.0.45-linux-amd64.tar`，再执行 `./devops.sh images status`，确认全部运行环境可用。
2. 执行 `./devops.sh update --check` 或 `./devops.sh upgrade --check /tmp/devops-v1.0.45-linux-x64.tar.gz`，只读核对版本、包结构和配置差异。
3. 备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`，按 `stop -> upgrade -> check` 完成程序升级。
4. 对比新版示例并合并四个 JVM 配置键，然后执行 `./devops.sh start`、`./devops.sh status` 和 `./devops.sh check`。
5. 从 `v1.0.43` 或更早版本累计升级时，保持 Docker Agent 与远程 Agent 在线，等待已有会话正文自动分批恢复。恢复期间历史可能短暂不完整，请勿重建、重置或删除 Agent。

也可以使用启动器安全修改非敏感值：

```bash
./devops.sh config set devops.launcher.jvm-xms-mb 512
./devops.sh config set devops.launcher.jvm-xmx-mb 2048
./devops.sh restart
./devops.sh status
./devops.sh check
```

本版本不新增域名、DNS、证书、Nginx 虚拟主机、公开端口或外部服务要求。现场配置和运行数据继续保留；程序回滚不会自动回滚数据库。

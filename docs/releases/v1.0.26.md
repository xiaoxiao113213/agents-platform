# Agents Platform v1.0.26

## 版本概览

`v1.0.26` 增强项目资料与 Agent 协作能力，同时优化对话排版、管理筛选和全局看板的真实性与稳定性。

## 主要更新

- 项目资料支持多级文件夹，可创建、移动、重命名和删除空目录，适合按业务模块组织同类资料。
- Agent 可先获取完整资料索引，再按目录读取已发布文档、链接或文件，减少反复搜索和无效探索。
- Agent 对话保留 Markdown 原始软换行、标题、列表和代码结构，阅读密度适中，不再过松或过度紧凑。
- 工作台移除不常用的审查与 SDK 实时运行时入口，资料和项目服务操作更集中。
- 对话运行期间减少无关工作区刷新，降低长回复过程中界面闪动。
- 最高管理员用户筛选保留账号名称，不再显示难以识别的数字 ID。
- 用户趋势按真实消息和使用活动统计；Agent 离线时看板会明确显示连接问题。
- Linux 升级预检失败时会可靠释放生命周期锁，修正配置或归档后可直接重试。
- JDK、Maven、pnpm 软件内容没有变化，继续复用 `v1.0.15` 软件离线包和服务器缓存。
- 修复了已知问题。

## 升级说明

1. 升级前备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`。
2. 执行 `docker load -i devops-runtime-images-v1.0.26-linux-amd64.tar` 导入本版本运行环境。
3. 执行 `./devops.sh upgrade --check /tmp/devops-v1.0.26-linux-x64.tar.gz`，确认版本、配置差异和包结构。
4. 完成累计升级后运行 `./devops.sh check`，启动服务并等待 Agent 重新连接。
5. 打开一个已有项目，检查资料目录和 Agent 资料索引；再打开一个包含标题、列表和代码块的老会话检查排版。
6. 在全局看板确认 Agent 在线状态、消息趋势和活跃用户符合实际使用情况。
7. 本版本没有新增平台 Nginx 参数，升级器会保留现场配置；执行 `nginx -t` 后再重载。
8. 需要离线安装 JDK、Maven 或 pnpm 时继续使用 `devops-runtime-software-v1.0.15-linux-amd64.tar.gz`。

同版本与降级仍会被拒绝。程序回滚不会自动回滚数据库，升级前必须保留可恢复备份。

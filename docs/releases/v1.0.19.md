# Agents Platform v1.0.19

## 版本概览

`v1.0.19` 重点修复浏览器断开后的会话占用、项目服务重复构建和失效产物提示问题，让老会话、服务恢复和文件下载状态更可靠。

## 主要更新

- 浏览器刷新、断网或关闭页面后，平台会及时取消上游任务并释放会话，不再长期提示上一条消息仍在处理中。
- 草稿会话切换为正式会话后，停止、恢复、状态查询和继续发送始终控制同一个运行任务。
- 项目服务恢复相同版本时只重启进程，不再周期性重复构建并覆盖正在使用的产物；版本或构建配置真实变化时才重新构建。
- 文件型产物被删除或改名时会显示原路径和明确的“文件已失效”状态，并给出重新生成或恢复文件的处理建议。
- 历史产物记录继续保留用于追溯，平台不会猜测文件的新路径，也不会因下载失败自动删除记录。
- JDK、Maven、pnpm 内容没有变化，不重复提供软件离线包，继续复用 `v1.0.15` 软件包和服务器缓存。
- 修复了已知问题。

## 升级说明

1. 升级前备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`。
2. 执行 `docker load -i devops-runtime-images-v1.0.19-linux-amd64.tar` 导入七个本版本运行环境。
3. 执行 `./devops.sh upgrade --check /tmp/devops-v1.0.19-linux-x64.tar.gz`，确认版本、配置差异和包结构。
4. 停止服务后执行正式累计升级，再运行 `./devops.sh check`、启动服务并确认 Agent 已重新连接。
5. 本版本没有新增 Nginx 参数；已经合并 v1.0.18 项目服务参数的现场无需重复修改。尚未合并的环境仍需按“Linux 安装与升级”页面补齐 WebSocket 分流、连接复用、长连接和下载非缓冲配置。
6. 进入一个老会话确认可以继续发送，再恢复一个真实项目服务并连续观察；对已删除文件的产物点击下载，应显示原路径和失效状态。
7. 需要离线安装 JDK、Maven 或 pnpm 时继续使用 `devops-runtime-software-v1.0.15-linux-amd64.tar.gz`。

同版本与降级仍会被拒绝。程序回滚不会自动回滚数据库，升级前必须保留可恢复备份。

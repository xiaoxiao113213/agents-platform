# Agents Platform v1.0.37

## 版本概览

`v1.0.37` 让项目内真实能力、工作区文件和平台用量更容易核对。团队可以从一个统一面板查看所有模型的 Token 消耗，也可以在 Agent 项目中准确识别 Skill、刷新实时目录并在独立页面使用终端。

## 主要更新

- Token 用量默认按用户汇总全部模型和 API Key，可切换按模型、API Key 或明细记录查看。
- 用量面板支持近 3 天、近 7 天、近 30 天和自定义日期，摘要、趋势、模型分布与 CSV 导出保持同一统计口径。
- 项目中的 `SKILL.md` 会按真实目录和能力元数据识别，已有 Skill 的贡献与使用情况可以正确反查。
- 工作区预览 Skill 文档时，名称、描述、版本、作者、标签和 Markdown 正文与 Skill 中心保持一致。
- 终端始终在独立浏览器标签页打开，不再挤占项目对话与工具区域。
- 实时工作区目录支持整体刷新和单目录刷新，便于及时查看 Agent 或外部工具产生的新文件。
- 修复了已知问题，并保持现有 Agent、项目、会话、能力、协作空间和主题数据兼容。

## 安装与升级

### 前置条件

- 继续使用 Linux x64、Java 21+、MySQL 8、Docker 和独立 Nginx。
- 升级前备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`。
- 确认磁盘空间足够保存并导入 6 个运行环境；运行环境包和主程序包必须同为 `v1.0.37`。
- 本版本没有新增域名、DNS、证书、公开端口或生产配置键，继续保留现场已有配置。

### 升级步骤

1. 执行 `docker load -i devops-runtime-images-v1.0.37-linux-amd64.tar`，再执行 `./devops.sh images status`，确认 6 个运行环境均可用。
2. 必要时先运行 `curl -fsSL https://mmmqaz.cn/releases/update-launcher.sh | bash`，并确认 `./devops.sh launcher-version` 不低于 `15`。
3. 执行 `./devops.sh upgrade --check /tmp/devops-v1.0.37-linux-x64.tar.gz`，确认版本、包结构和现场配置差异。
4. 完成备份后执行 `./devops.sh stop`、`./devops.sh upgrade /tmp/devops-v1.0.37-linux-x64.tar.gz`、`./devops.sh check`、`./devops.sh start` 和 `./devops.sh status`。
5. 不要覆盖现场 `application.properties` 或 `nginx/devops.conf`。

### 产品内验收

1. 打开首页 Token 用量，切换近 3 天、近 7 天、近 30 天与自定义日期，确认总量和趋势随范围更新。
2. 在同一统计范围内切换用户、模型、API Key 和明细维度，确认总量保持一致，并下载一份 CSV 核对维度列。
3. 进入包含既有 `SKILL.md` 的 Agent 项目，确认 Skill 贡献和项目使用情况可见，文件预览中的元信息与 Skill 中心一致。
4. 在文件工作台刷新整体目录和一个已展开目录，确认新文件出现且其他展开状态保留。
5. 点击终端入口，确认在独立浏览器标签页打开并可正常输入命令。

### 常见问题

- Skill 仍未识别：确认文件位于当前项目可访问目录、名称为 `SKILL.md`，并检查 YAML 元数据格式是否完整。
- 刷新后看不到文件：确认文件已写入当前 Agent 项目目录，并检查远程 Agent 是否在线以及当前用户是否有项目访问权限。
- 用量数据为空：确认所选日期范围内存在已完成的 Agent 请求，并清除模型、API Key 或用户筛选后重试。
- 升级预检提示配置差异：保留现场文件，以包内 `.example` 为参考逐项合并。

### 全新安装

全新安装执行 `./devops.sh install`。安装完成后登录平台，先确认领域主题和平台名称，再创建或选择 Agent 项目并配置所需 Skill、MCP 与协作空间。

同版本与降级仍会被拒绝。程序回滚不会自动回滚数据库，升级和回滚都不会覆盖现场配置、项目工作区、文件与运行数据。

# Agents Platform v1.0.16

## 版本概览

`v1.0.16` 重点修复项目服务长时间运行后访问超时和网络流量持续升高的问题，并在全局看板中加入逐 Agent、逐服务的健康诊断。

## 主要更新

- 项目服务传输增加流量保护。单个响应过快或浏览器处理过慢时，只中止受影响的访问，不再影响同一 Agent 的其他项目服务。
- 项目服务长时间运行、Agent 断线重连和平台重启后的资源释放更加完整，减少必须重启才能恢复的情况。
- 全局看板新增项目服务总数与异常数，并在每个 Agent 下汇总服务健康状态。
- 新增项目服务诊断明细，可查看 Agent 与服务通道在线状态、当前请求、连接、数据积压、最近健康检查及明确异常原因。
- 升级预检在不同 Linux 语言环境下保持一致，不再出现配置键排序告警。
- 延续对话页面稳定、历史会话恢复、Linux 终端输入、离线软件安装和项目服务重建恢复等既有修复，并纳入统一回归检查。
- 修复了已知问题。

## 配置与兼容性

- 本版本没有新增或删除生产配置项。
- 现场 `application.properties`、Nginx 实际配置、项目工作区、会话、Skill、MCP、运行数据和日志在累计升级时继续保留。
- 七个内置 Agent 运行环境统一更新为 `v1.0.16`；已有 Agent 的服务代码会自动更新，基础运行环境在重建 Agent 后生效。
- JDK、Maven、pnpm 软件内容没有变化，本版本不重复提供软件离线包；已有环境继续复用缓存，新环境使用 `v1.0.15` 软件包。

## 升级说明

- `v0.0.1` 及后续正式版本都可以直接累计升级到 `v1.0.16`，无需补装中间版本。
- 已安装客户先获取 `devops-runtime-images-v1.0.16-linux-amd64.tar` 并执行 `docker load -i devops-runtime-images-v1.0.16-linux-amd64.tar`，确认导入成功后再执行 `./devops.sh update`。
- 需要为 Agent 安装 JDK、Maven 或 pnpm 且服务器尚无缓存时，将 `devops-runtime-software-v1.0.15-linux-amd64.tar.gz` 一次解压到 `/opt/devops/devops/runtime-software-cache`；平台会自动校验并复用。
- 升级前建议执行 `./devops.sh update --check`；该检查不会拉取镜像，也不会修改程序、配置、数据、日志或数据库。

## 升级后验收

1. 执行 `./devops.sh check` 和 `./devops.sh status`，确认平台运行正常。
2. 打开全局看板，确认项目服务总数、异常数和逐服务诊断可以正常显示。
3. 打开一个已有 Agent 的项目服务并持续访问，确认页面正常且异常数不增加。
4. 重启一个 Agent 后再次打开原项目服务，确认服务能够恢复；如项目自身配置错误，按看板中的问题原因处理。

# Agents Platform v1.0.46

发布日期：2026-08-28

`v1.0.46` 将开发者应用统一为可独立登录的平台账号。团队可以使用一个账号、一套平台权限和一个长期 SDK API Key 构建客服服务、Agent 管理台或其他业务系统，而不需要维护另一套应用授权模型。

## 本次更新

- 开发者应用可以使用账号密码登录平台，并像普通团队成员一样分配角色、菜单、Agent 与项目权限。
- 每个应用只保留一个有效 SDK API Key，支持最高管理员创建和轮换，也支持应用账号在个人中心自助管理。
- SDK 调用继续遵守平台现有角色、资源归属和分享规则，使用 API Key 不会自动扩大权限。
- TypeScript 和 Java SDK 新增通用平台接口调用能力，可访问应用账号已经获权的后台接口。
- 新增 Spring Boot + React Agent 管理控制台案例，覆盖首次配置、Agent 创建与生命周期、项目、会话、历史、文件、产物、Skill、MCP、项目服务和诊断设置。
- 客服服务与 Agent 管理案例均使用本地 Spring Boot BFF 加密保存长期 Key，进入业务界面后浏览器请求不直接携带平台 Key。
- 对话历史继续聚焦用户输入和模型正式回答；执行期间只保留最后一个工具状态，正文开始后自动收起。
- 六个内置 Agent 运行环境统一更新为 `v1.0.46`。

## 升级后重新建立开发者应用

旧版本中的开发者应用测试授权和多个 Key 不再沿用。升级完成后按以下顺序重新配置：

1. 使用最高管理员账号进入“开发者中心”，创建新的开发者应用账号和独立登录密码。
2. 分配普通角色、菜单以及 Agent/项目数量配额。
3. 按业务边界分享 Agent 的全部项目或指定项目；应用账号登录平台核对实际可见范围。
4. 创建唯一 SDK API Key，并将它保存到可信服务端的加密配置中，不要写入前端代码、浏览器存储或公开仓库。
5. 使用 SDK 调用一个已授权接口和一个未授权资源，确认正常结果与拒绝边界都符合预期。
6. 后续轮换 Key 时同步更新调用方；旧 Key 会立即失效。

## 安装与升级

1. 执行 `docker load -i devops-runtime-images-v1.0.46-linux-amd64.tar`，再执行 `./devops.sh images status`，确认六个运行环境可用。
2. 执行 `./devops.sh update --check` 或 `./devops.sh upgrade --check /tmp/devops-v1.0.46-linux-x64.tar.gz`，只读核对版本、包结构和配置差异。
3. 备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`，按 `stop -> upgrade -> check -> start -> status` 完成升级。
4. 登录平台核对普通账号、Agent、项目、会话历史与分享关系，再按上节步骤重新创建开发者应用。
5. 下载 Developer Center 中的 SDK 或完整案例，在独立测试环境配置新 Key 后验证业务调用。

本版本没有新增域名、DNS、证书、Nginx 虚拟主机、公开端口或外部服务要求。现场配置和运行数据继续保留；程序回滚不会自动回滚数据库。

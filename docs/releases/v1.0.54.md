# Agents Platform v1.0.54

发布日期：2026-09-04

`v1.0.54` 让项目切换、能力查找和模型连接配置更直接，并提升远程开发引擎在长时间工具任务中的连接稳定性。

## 本次更新

- “项目”成为统一入口，左侧直接展示最近项目和全部项目；Skill 与 MCP 合并为“能力广场”，可在页面顶部切换。
- 模型连接可以同时支持协作引擎和开发引擎，并分别配置平台内网地址与远程 Agent 外网地址。
- 最近项目遇到临时网络故障时会有限重试；仍失败时保留上次结果并提供主动重试，不会持续请求。
- 协作空间事项支持多选后批量修改状态，只展示全部选中事项共同可用的目标状态。
- 远程开发引擎在长时间工具执行期间保持连接；失败历史会保留明确状态、处理时长和重试提示。
- 两种执行引擎使用一致的消息布局，平台能力调用与终端命令会按真实类型展示。
- 六个内置 Agent 与独立 IM Gateway 运行环境统一更新为 `v1.0.54`；既有 SDK、CLI 和 IM 渠道兼容关系保持不变。

## 升级前准备

1. 备份 `devops` 数据库、现有安装目录、`application.properties`、`nginx/devops.conf` 和 `im-gateway.env`。
2. 确认宿主机仍满足 Java 21+、MySQL 8 和 Docker Engine 要求。
3. 如使用远程 Agent，确认外网模型地址可从远程执行机访问；仅能在平台内网访问的地址应保留在内网地址字段。
4. 如使用 IM 机器人，保留现有 Gateway 共享令牌和 WS/WSS 地址，本版本无需为 IM 新增公开端口。

## 安装与升级

1. 执行 `docker load -i devops-runtime-images-v1.0.54-linux-amd64.tar`，再执行 `./devops.sh images status`，确认六个 Agent 环境和 IM Gateway 均可用。
2. 执行 `./devops.sh upgrade --check /tmp/devops-v1.0.54-linux-x64.tar.gz`，只读核对版本、包结构和配置差异。
3. 对照新版 `application.properties.example` 检查现场配置；升级程序会保留现有配置，不要用示例文件覆盖现场文件。
4. 完成备份后执行 `./devops.sh stop`、`./devops.sh upgrade /tmp/devops-v1.0.54-linux-x64.tar.gz`、`./devops.sh check`、`./devops.sh start` 和 `./devops.sh status`。
5. IM Gateway 独立运行；需要启用时执行 `./im-gateway.sh start`，不使用 IM 时可以保持停止。

## 升级后验收

1. 打开“项目”，确认最近项目、范围切换和“全部项目”可用；进入“能力广场”往返切换 Skill 与 MCP。
2. 新建或编辑一个模型连接，分别核对引擎选择、内网地址、外网地址和模型列表；不要在测试中保存无效地址。
3. 使用远程 Agent 执行一轮包含工具调用的开发引擎对话，确认任务过程持续更新，完成后正文、工具类型和处理时长正确。
4. 在协作空间选择多个可流转事项，确认批量操作只提供共同目标状态，并在确认前核对选择数量。
5. 暂时阻断最近项目请求后恢复网络，确认页面保留上次结果并可通过“重试”恢复。

升级前必须保留数据库与现场配置备份。程序回退不会自动回退数据库，涉及回滚时请使用升级前备份。

# Agents Platform v1.0.23

## 版本概览

`v1.0.23` 重点提升多会话、长时间任务和项目服务的稳定性，同时完善 Agent API Key 权限、自动版本刷新与安装体验。

## 主要更新

- 新对话在发送首条消息后才正式建立，空白草稿不再进入历史列表；同时创建、切换和运行多个会话时，各自的消息和运行状态保持隔离。
- 超大历史会话会省略重复的二进制正文并控制单页大小，执行机暂时不可用时也不再阻止删除平台会话。
- 长时间 Workflow、Task 和子 Agent 保持控制连接，超过十分钟的后台工作仍可继续回传进度并正常结束。
- 项目服务按当前操作系统使用统一生命周期脚本，支持单服务创建、更新、状态、日志、启停、重启和卸载，不再为了一个服务重建其它服务。
- 项目服务端口、PID、进程树和健康路径在启动前后统一核验，删除后确认释放端口；资源不足时会给出明确配置建议。
- Agent 的 API Key 始终按当前所有者权限过滤，转移 Agent 时自动移除新所有者无权使用的 Key，并同步修正会话和自动任务。
- 模型服务配置只在任务运行时使用，不写入用户或项目设置文件；对话、Workflow、Task 和子 Agent 使用一致的服务端配置。
- 页面发现服务器已升级后会自动刷新资源，长期开着页面的用户无需手工刷新即可进入新版本。
- 最高管理员可按用户筛选 Agent；普通用户不显示该筛选入口。
- 对话附件单文件与单次总量均支持 500 MiB，Maven 离线安装继续内置阿里云依赖和插件镜像。
- JDK、Maven、pnpm 软件内容没有变化，继续复用 `v1.0.15` 软件离线包和服务器缓存。
- 修复了已知问题。

## 升级说明

1. 升级前备份数据库、安装目录、`application.properties` 和 `nginx/devops.conf`。
2. 执行 `docker load -i devops-runtime-images-v1.0.23-linux-amd64.tar` 导入本版本运行环境。
3. 执行 `./devops.sh upgrade --check /tmp/devops-v1.0.23-linux-x64.tar.gz`，确认版本、配置差异和包结构。
4. 完成累计升级后运行 `./devops.sh check`，启动服务并等待 Agent 重新连接。
5. 打开一个已有会话和一个新对话，验证发送、切换、停止与继续执行；再运行一次长任务确认进度持续回传。
6. 在一个真实项目中依次验证服务状态、日志、重启、停止和启动，确认页面展示的端口与应用实际监听一致。
7. 页面拒绝嵌入时，检查项目应用及其专属代理的 iframe 响应头、HTTPS、Cookie 与登录跳转；不要关闭项目自身的业务鉴权。
8. 本版本没有新增平台 Nginx 参数，升级器会保留现场配置；执行 `nginx -t` 后再重载。
9. 需要离线安装 JDK、Maven 或 pnpm 时继续使用 `devops-runtime-software-v1.0.15-linux-amd64.tar.gz`。

同版本与降级仍会被拒绝。程序回滚不会自动回滚数据库，升级前必须保留可恢复备份。

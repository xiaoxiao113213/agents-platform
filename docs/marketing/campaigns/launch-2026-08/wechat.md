# 微信公众号首发文章

## 标题

让 Agent 进入项目，而不是停在聊天框里

## 摘要

Agents Platform 把项目、会话、文件、任务、企业系统和交付物放进同一工作现场，让 Agent 从回答问题走向完成真实工作。

## 正文

过去一年，团队使用 AI 的门槛越来越低。写一段代码、解释一个报错、整理一份材料，几乎都可以从对话开始。

但当任务进入真实项目，问题马上变得不一样。

一次跨端故障可能同时涉及前端状态、后端接口、SSE 或 WebSocket、会话持久化和运行时事件；一个经营分析需要先确认数据库结构和指标口径，再形成可复查 SQL 与可访问看板；一个项目 Issue 也不只是标题和描述，还包含评论、图片、附件、代码现场与验收状态。

如果 Agent 只有聊天框，人仍然要反复搬运上下文、执行命令、保存文件、核对结果，再把过程写回原来的业务系统。模型回答了问题，但工作没有真正闭环。

这正是我们构建 Agents Platform 的原因。

## 一份 Agent，就是一份持续存在的项目现场

在 Agents Platform 中，每个 Agent 都拥有项目目录、会话、文件、任务和交付物。团队成员可以在权限和数量限制内创建 Agent，也可以把 Agent 分享给其他成员，共同进入同一份项目现场。

Agent 可以在授权范围内连接团队已有的代码、数据库、Issue、流水线、质量、基础设施和可观测系统。用户给出的不再是一个孤立问题，而是一项目标。Agent 可以读取上下文、执行步骤、形成文件或系统结果，并保留可供人工复核的过程。

这种方式适合持续工作，而不只是一次性问答。项目、会话和交付物都留在原来的工作空间里，下一轮任务可以在已经建立的事实基础上继续。

## 七类内置 Agent，覆盖从研发到内容交付

平台当前提供七类内置 Agent：

- 通用 Agent：软件开发、排障、自动化和文档交付；
- 网站开发 Agent：网站和 Web 应用的设计、实现与浏览器验收；
- Issue 处理 Agent：接管需求和 Bug，完成修改、验证、评论与人工验收闭环；
- Grafana Agent：把多套数据源的指标需求落成可继续迭代的 Dashboard；
- PPT Agent：把散乱材料整理成可编辑的 PPTX、PDF 和预览；
- 视频 Agent：从主题完成脚本、旁白、字幕、工程和 MP4 成片。

官网同时展示了十类工作案例，包括从一张截图定位跨端故障、连续处理项目 Issue、生成经营大盘、制作董事会汇报、完成培训视频和追踪生产故障根因。

## 自托管不等于没有边界

Agents Platform 由客户部署在自己的 Linux 环境中。项目、会话、文件、数据库连接和业务系统数据由部署方管理，官网不会自动取得这些内容。

与此同时，Agent 可以执行复杂工作，结果仍应根据业务风险接受人工复核。生产变更、数据写入、对外发布和重要决策需要明确的确认流程。平台提供的是可持续工作的基础设施，不是“无需治理的全自动承诺”。

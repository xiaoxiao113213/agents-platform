# 活动 Brief：让 Agent 进入项目

## 目标

让国内研发、数据、运维、产品和企业数字化团队理解 Agents Platform 与普通 AI 聊天产品的差异，并引导有自托管需求的团队访问官网、查看能力案例或下载正式版本。

## 核心受众

- 希望把 AI 引入真实研发流程的技术负责人、研发效能和平台团队。
- 需要处理数据库、看板、Issue、网站、PPT 或视频交付的业务团队。
- 重视数据边界、权限控制和本地部署的企业用户。

## 用户问题

团队已经可以和模型聊天，但真实工作仍散落在代码仓库、数据库、Issue、流水线、文件和业务系统中。聊天结果缺少项目现场、执行过程、可下载产物和持续协作关系。

## 主叙事

Agents Platform 不把 Agent 留在聊天框里。每个 Agent 拥有项目、会话、文件、任务和交付物，并在授权范围内连接团队已有系统。用户给出一项目标，Agent 沿真实上下文完成一整段工作，留下可以检查、继续编辑和人工验收的结果。

## 可核验事实

- 七类内置 Agent：通用、数据库、网站开发、Issue 处理、Grafana、PPT 和视频。
- 十类官网工作案例覆盖研发工程、数据运营、内容交付和企业流程。
- 支持团队创建和共享 Agent，并通过权限控制能力范围。
- 客户在自己的 Linux 环境中部署，官网不会自动取得平台内的项目、会话和业务数据。
- 当前正式版本为 `v1.0.5`，支持全新安装和从 `v0.0.1` 及后续正式版本累计升级。
- 官方未修改的二进制安装包可供个人或同一法人实体免费自托管用于内部业务；产品不是开源软件。

## 首轮内容角度

1. 为什么企业 Agent 不能只有聊天框。
2. 从一张截图到跨端故障修复，Agent 如何沿完整链路工作。
3. Issue、数据库和 Grafana 为什么应与项目一起进入工作区。
4. 自托管、权限和人工确认如何建立可控边界。

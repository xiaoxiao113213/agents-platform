# Agents Platform 宣传运营

本目录保存 Agents Platform 的长期公开传播策略、品牌口径、平台规则、活动内容和发布记录。目标不是把同一篇广告复制到多个网站，而是基于同一组可核验事实，为不同读者提供有用的案例、教程和版本信息。

## 事实来源

公开内容按以下顺序取材：

1. 当前正式版本的 `docs/releases/vX.Y.Z.md` 客户版说明。
2. 官网 `src/content/capabilities.ts`、`src/content/useCases.ts` 和 `src/content/releases.ts`。
3. 仓库根目录 `README.md`、`LICENSE` 和官网公开安装指南。

主平台仓库的内部版本验收记录不得直接用于公开文案。数据库迁移编号、凭据处理、加密签名、测试数量、镜像构建推送和内部配置真源不得出现在宣传内容中。

## 长期内容结构

- 产品认知：Agent 为什么需要项目、文件、任务、权限和交付物。
- 工作案例：Issue 闭环、跨端排障、数据库与 Grafana、网站、PPT、视频和定时简报。
- 技术实践：Linux 自托管、安装升级、模型连接、远程 Agent 和企业系统接入。
- 版本更新：只表达客户可感知的功能、稳定性、兼容性和升级体验。
- 信任内容：数据边界、人工确认、软件许可、部署责任和适用场景。

## 版本触发流程

1. 正式版本完成全部发布门禁、GitHub Release 和远端附件下载验证。
2. 读取对应客户版版本说明，建立 `campaigns/vX.Y.Z/` 活动目录。
3. 提取一个主叙事、三项用户价值、截图清单、FAQ 和统一落地页。
4. 分别生成公众号、知乎、开发者社区、小红书和视频文案。
5. 核对品牌口径、许可、版本号、下载链接和升级边界。
6. 登录各平台生成草稿，人工检查排版、图片和平台提示。
7. 获得发布确认后执行发布，回读页面并登记公开 URL。
8. 发布后 7 天记录阅读、点击、下载、咨询和有效反馈，决定补充内容。

正式版本完成前不得发布“已经上线”或可下载的版本公告。可以准备草稿，但不能提前给出未验收的下载承诺。

## 发布控制

- 登录、扫码、短信验证码、实名和风控验证由账号所有者完成。
- 浏览器会话按平台隔离并持久化，密码、Cookie 和 Token 不写入仓库。
- 默认采用“草稿完成”和“最终发布”两个检查点。
- 禁止刷量、批量私信、伪造评价、冒充客户或绕过平台限制。
- 技术社区以解决问题和分享实践为主，不发布纯广告或无差别转载。
